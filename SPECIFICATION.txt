FlowGet 独立实现规格 / 阶段记录
源码版本 0.3.0，2026-10-19；附带 Windows 可执行文件仍为 0.1.0

目标
  分阶段覆盖 IDM 类桌面下载器的用户可见能力。所有实现自行设计。
  不以破解试用、恢复激活码、补丁修改原软件为目标。

证据与来源边界
  OBS-01：本机安装文件为
    C:\Program Files (x86)\Internet Download Manager\IDMan.exe
    版本信息 6.43.12.2，x86 PE，大小 6,200,176 字节。
    SHA-256 e7286b28936d97bb6dca68c6cf552aa951341b47a0bb8909589849b628af9f05
  OBS-02：REA inspect_pe_resources
    Evidence ev_7448609bd71309be59ce3fbbc6e779a10b6886934e40c4c6fa0688f9fdb16de1
    887 个资源目录项，436 个资源。仅清点元数据，没有复制资源内容。
    资源树只能证明静态资源存在，不能据此断言下载算法或运行时行为。
  OBS-03：本轮及前轮实际 IDM 界面观察。
    主界面有新建、继续、停止、选项、计划、开始/停止队列、站点抓取入口。
    列表包含名称、大小、状态、速度、剩余时间等列。
    左侧有所有任务、完成/未完成、压缩/文档/音乐/程序/视频等分类。
    关于页显示 6.43 Build 12、Trial、未注册版本。
    入口可见只证明入口存在；未据此声称这些功能内部算法已还原。
  LIMIT-01：REA 的原生反编译提供器未配置。
    Ghidra/IDA/Kuna 不可用，Hopper 不支持当前 Windows 主机。
    没有反编译 IDM 下载逻辑，没有对其做运行时内存注入、补丁或流量截获。
  STD-01：HTTP Range、If-Range、Content-Range、ETag 依据 RFC 9110。
    https://www.rfc-editor.org/rfc/rfc9110.html
  DESIGN：以下持久化、并发、恢复和视觉方案均为独立设计；不是 IDM 内部事实。

第一阶段：HTTP 下载核心与桌面界面
  已实现：新建、暂停/继续、状态列表、分类、搜索、详情、进度与速度。
  已实现：固定分段范围、每段独立文件、有限重试、未知长度单连接。
  已实现：JSON 原子保存任务；活跃任务重启后变为暂停；不擅自自动恢复。
  已实现：ETag 与长度一致才复用分段；每个分段核对 Content-Range。
  已实现：没有强 ETag 时完整单连接传输，避免拼接不相容的表示版本。
  已实现：所有分段成功才合并；分段线程退出之后才更改为最终状态。
  已实现：原子硬链接发布，不覆盖目标；SHA-256 可选预期值。
  已实现：连接数/并发任务数、总限速、一次性定时队列。
  已实现：本机单实例锁、退出保存、Windows 系统 curl 后端。
  暂不保证：速度与 IDM 相当、每个站点兼容、低磁盘空间恢复。

第二阶段：浏览器与请求上下文（部分实现）
  已开发：Edge / Chrome 扩展，明确的“用 FlowGet 下载”链接右键菜单和弹窗。
  已开发：Native Messaging 桥接、明确来源白名单、本地任务收件箱与幂等导入。
  已开发：注册/卸载脚本，仅修改当前用户下本程序自己的宿主项。
  已开发：Content-Disposition / filename*、批量 TXT 链接导入与导出。
  已测试：消息字节封装、未知扩展拒绝、非法 URL 拒绝、重放去重、扩展消息逻辑。
  未安装：没有在用户 Edge/Chrome 中加载扩展或写入其宿主注册。
  未验证：真实浏览器调用链；需安装后才可将本阶段标为完成。
  未实现：自动下载接管、登录型链接的请求上下文、自动发现更新地址。
  0.2.0 已实现：手动替换下载地址；重新下载，不跨地址复用旧分段。
  以下是后续规格，不能视为已实现：
  显式用户触发后，最小化传递 URL、User-Agent、Referer、必要 Cookie。
  跨域重定向不泄漏 Cookie/Authorization，日志脱敏，敏感上下文不默认持久化。
  验收：真实 Edge 点击、受控登录下载源、关闭扩展后的回退行为。
  Native Messaging 官方依据：
    https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging
    https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging

第三阶段：队列与桌面常用能力（部分实现）
  0.2.0 已实现：队列内多选排序并持久化、单任务限速、一次性定时停止。
  0.2.0 已实现：暂停任务编辑、手动更新地址、列表视图排序、实时速度图、分段详情。
  调度顺序与视图排序独立；移动任务不抢占已运行连接。
  定时停止暂停活跃任务，保留等待任务；重启后保持队列停止。
  0.3.0 已实现：持久化多队列、任务归属与迁移、各队列并发上限和一次性计划。
  0.3.0 已实现：队列轮流获取全局空闲槽位、独立启停、停止等待与默认队列迁移。
  仅可移动已停止的任务；默认队列和非空队列不可删除；不抢占已有任务。
  未实现：分类目标目录、周期计划、托盘与完成提醒。
  未实现：每站点连接上限、域名限速、代理配置与可选认证。
  动态分段重分配、预分配与磁盘空间检查、较低额外磁盘占用。
  验收：大文件长期传输、强制结束恢复、磁盘满、网络切换和真实站点矩阵。

第四阶段：抓取、FTP 与媒体（部分实现）
  0.3.0 已实现：同站点 HTML 链接/资源发现、可选目录限制、深度与文件类型筛选。
  0.3.0 已实现：robots.txt、范围及重定向检查、页面/字节/结果数预算、取消与预览。
  0.3.0 已实现：选中资源导入目标队列，去重并暂停，复用现有下载与校验流程。
  抓取不执行脚本、不处理登录 Cookie、不重写离线镜像链接；资源地址保留来源页。
  0.3.0 已实现：FTP 匿名/账号登录、被动二进制单连接、SIZE/MDTM 探测、REST 续传。
  FTP 文件标识是大小与修改时间，不等于强内容标识；元数据变化时丢弃旧分段，
  缺少元数据或 REST 被拒绝时从头下载；前后元数据变化时不发布成品。
  FTP 密码仅存内存；非匿名任务重启后须重新登录；不使用 HTTP 代理。
  FTP 复用全局/单任务限速、重试、暂停、多队列、哈希和不覆盖目标的发布逻辑。
  未实现：FTPS/SFTP、FTP 多连接分段、自动账号保管。
  以下媒体能力尚未实现：
  用户授权网页的非加密 HLS/DASH 播放列表与分段下载，独立合并工具。
  验收：本地测试站、多级链接、媒体时长与内容比对、暂停和恢复。

测试定义
  本地受控 HTTP 源验证：并行、忽略 Range、未知长度、无 ETag、空文件、
  重定向、断线重试、坏范围、坏哈希、404、同名保护、跨实例续传、
  ETag 变化重下、队列并发、计划启动、限速、文件名/地址安全。
  真实 HTTPS：从 PyPI 获取 6 个 wheel，并与 PyPI 发布的 SHA-256 对照。
  本地通过不能推定所有互联网源兼容；具体结果保存在 verification。
  0.3.0 新增：实际 FTP 控制/数据套接字测试，覆盖登录、跨实例 REST、重下、
  传输中变化、空文件/未知大小、缺失资源、哈希不匹配及命令控制字符拒绝。
  0.3.0 新增：多队列并发/公平调度/独立启停/计划/迁移/移动/批量去重。
  0.3.0 新增：受控网站的 robots、跨目录/端口/跳转、深度、字节预算、取消及下载导入。
  0.3.0 新增：真实 Tk 窗口中的队列筛选、任务移动、FTP 登录、抓取预览及导入。
  本轮不将本地协议测试视为真实互联网 FTP、Windows curl 或重新打包 EXE 验证。
